# Amazon ML Challenge 2026: Business Entity Resolution

Match Source-1 business records to their Source-2 and Source-3 counterparts (US, India, and France in test only).
The metric is macro F0.5 per S1 entity, with singletons included.
Pipeline code: [`code/business_entity_resolution/`](code/business_entity_resolution/README.md).

## 1. Local setup (VS Code), once

```bash
git clone -b claude/entity-resolution-ml-c287bq https://github.com/AayushDeshmukh9090/Amazon-ML-Challenge-2026.git
cd Amazon-ML-Challenge-2026
python -m venv .venv
# macOS/Linux: source .venv/bin/activate     Windows: .venv\Scripts\activate
python run.py setup
```
Then copy the data into `dataset/` (and `student_resource/utils/validate_submission.py` into `utils/`),
open the folder in VS Code, select the `.venv` interpreter, and run `python run.py check-data`.

## 2. What to run where

| task | command | where | cost |
|---|---|---|---|
| code still runs? | `python run.py smoke` | local | ~1 min, synthetic data |

In VS Code the same commands are under **Terminal → Run Task → "ER: …"**. The debug configs
(F5) run the pipeline on `dataset_sample/` so you can set breakpoints in the features.

## Large-scale pipeline (v2, built from the EDA)

Data: train 2.2M S1 x 10.3M S2+S3, test 1.7M x 10M. GT is strictly 1-to-1 from the S2/S3 side,
country is a safe block key, addresses are the reliable signal, and distractors are near-duplicates.

| step | module | what |
|---|---|---|
| synonyms | `synonyms.py` | learn token maps from training pairs (Indic-script names/states, city aliases) |
| prep | `prep.py` | stream + normalise every file once (parallel) -> `work/prep/*.parquet` |
| block | `block.py` | IDF-weighted token-overlap search per country, reverse (S2/S3->S1) + forward -> `work/cands/`, `work/blocking_report.md` |
| features2 | `features2.py` | ~120 pair + competition features on the pruned pairs -> `work/feat/` |
| train2 | `stage2.py` | LightGBM, 2-fold OOF by S1 entity, 1-to-1 decision tuned for macro F0.5 -> `work/stage2_report.md` |
| predict2 | `stage2.py` | `output/matching_results.tsv`, `output/candidate_pairs.tsv` |

`python run.py full` runs everything, and `stage1` / `stage2` run the halves. On the full data,
run it on Modal (32 CPU / 128 GB).

## 3. Heavy runs on Modal (recommended: more cores, can run detached)

```bash
pip install -r remote/requirements.txt && modal setup     # once
modal run remote/modal_app.py --upload --task upload      # once, and whenever dataset/ changes
modal run remote/modal_app.py                             # train + predict on your CURRENT local code
modal run remote/modal_app.py --task eda                  # any task: eda|blocking|features|train|predict|all
modal run --detach remote/modal_app.py                    # survives laptop sleep; later: --task download
```
Results land in the local `output/`, `work/` (summary, model, OOF) and `reports/eda/`, so
`python run.py validate` and `zip` work right after.

## 4. Heavy runs on Colab

Upload `dataset/` to `MyDrive/amazon_ml_2026/dataset/`, add a Colab secret `GITHUB_TOKEN`
(read-only token for this repo), and run `remote/colab_runner.ipynb` top to bottom. It clones this
branch, keeps `work/`, `output/` and `reports/` on Drive (a disconnect loses nothing, and cached
features are reused), then trains, predicts and validates. Push code changes from VS Code first,
because the notebook pulls the branch.

## Workflow loop
edit code in VS Code → `run.py smoke` → `run.py quick` (sample) → push / `modal run` (full) →
read `work/train_summary.json` → `run.py validate` → upload `output/matching_results.tsv`.

The feature cache (`work/cache_*.pkl`) is keyed on the data files and the blocking config.
After changing **feature code**, add `--no-cache` (e.g. `modal run remote/modal_app.py --extra "--no-cache"`).
